# Juleflet redesign — implementation spec

Source of truth for the visuals: the rendered mockup artboards in
`/Users/ahle/repos/julehjerte-redesign/docs/redesign/mockups/`
(`Main.dc.html` = front page 1440, `Tablet.dc.html` 1024, `TabletPortrait.dc.html` 768, `Mobile.dc.html` 390,
`Detail.dc.html`, `HowTo.dc.html`, `Om.dc.html`, `Editor.dc.html`). They are generated by `build-artboards.mjs`
in the same directory, which contains the exact CSS (the `HELMET` constant) and every markup helper
(`hang`, `card`, `categorySection`, `hero`, `detail`, `guideSvg`, `om`, `editor`, `galleryFrame`, `landPine`).
Read that file when you need an exact value; open the `.dc.html` files in a browser to see the result.
Screenshots of the mockups exist next to them (`*.png`).

The site is Danish-first with an English mirror under `/en/`. Every user-facing string below is Danish and
needs an English equivalent in `src/lib/i18n/translations.ts`.

## 1. Palette and type

Define as CSS custom properties on `:root` (replace the current blue/teal palette everywhere):

| token | value | use |
|---|---|---|
| `--page` | `#f9f9f3` | page background — identical to the landscape's foreground snow, so hero and gallery join without a seam |
| `--sky` | `#d6e1d0` | hero / detail-scene background (the landscape's sky) |
| `--cream2` | `#e6ece2` | footer, soft panels |
| `--sage` | `#b5c9b7` | inactive dots, dashed borders |
| `--sage-dark` | `#7f9c86` | secondary strokes |
| `--green` | `#2e5041` | nav links, outline buttons, icons, category headings |
| `--deep` | `#1c3329` | headings |
| `--red` | `#c41e2a` | primary buttons, ribbons, selection ring, active nav |
| `--ink` | `#1e2a25` | body text |
| `--muted` | `#5f6d66` | secondary text |
| `--line` | `#cfd9cf` | borders, pills |
| `--white` | `#ffffff` | cards, buttons |
| `--gold` | `#e0b75a` | stars |
| `--blue` | `#4a90b8` | focus rings only |
| `--muted-on-sky` | `#4d594f` | secondary text painted on `--sky` (see below) |

`--muted` on `--sky` measures 4.02:1, under the WCAG AA 4.5:1 minimum for body text, so text that sits on the
hero/detail sky uses `--muted-on-sky` (5.4:1) instead; `--muted` is unchanged everywhere else. For the same
reason the focus ring is `outline: 3px solid var(--blue)` **plus** `box-shadow: 0 0 0 2px var(--page)`:
`--blue` alone is 2.60:1 against `--sky`, and the pale inner ring keeps one edge of the indicator above the
3:1 that SC 1.4.11 asks for on every background.

Font stays `'Helvetica Neue', Helvetica, Arial, sans-serif`, antialiased. Headings weight 600, h1 line-height 1.05.
Buttons: height 44, padding 0 20, radius 10, 15px/600, icon 18px + 8px gap. Kinds: primary (red bg, white text),
outline (white bg, 1.5px green border, green text), ghost (transparent, 1.5px `--line` border, green text),
dark (green bg, white text). Pills (EN, GitHub): 13px/600 green, 1.5px `--line` border, radius 999, white bg.

## 2. The landscape drawing

`landscape.svg` (2172×724) is the user's own drawing. Use the copy `landscape-lifted.svg` from the design
directory: it is identical except that the foreground snow bank is lifted a few units where the original dipped
below the bottom edge, so the drawing always ends in `#f9f9f3` snow (= `--page`). Put it in the repo as
`src/lib/assets/landscape.svg` and build a `Landscape.svelte` component that inlines it once per page
(`import svg from '$lib/assets/landscape.svg?raw'`, strip the outer `<svg …>` open tag, `<title>` and `<desc>`,
and emit `<svg class={cls} viewBox="0 0 2172 724" preserveAspectRatio="xMidYMax meet" aria-hidden="true">…</svg>`).

Its `<defs>` carry reusable ids that other inline SVGs on the same page reference with `<use href="#…">`:
`pine-a`, `pine-b`, `pine-c` (fir silhouettes: tip at (0,0), base at y = 202, width about ±65),
`snow-cap` (frost, use with `fill="#fbfcfa"` in the same group), `star` (34 units, gold), gradients
`sky`, `distant-hill`, `middle-hill`, `near-hill`, `snow`. Because of these ids the drawing may be inlined only
once per page. A fir is placed with `<g transform="translate(x tipY) scale(kx ky)" fill="#35503f"><use href="#pine-c"/><use href="#snow-cap" fill="#fbfcfa"/></g>`
where `k = height / 202`; negative `kx` mirrors it. Fir fills: `#35503f`, `#3b5d46`, `#3e5948`, `#34523f`.
See `landPine()` in the generator.

Placement rules (front-page hero; detail page is the same idea):
- Hero `background: linear-gradient(var(--sky), var(--sky)) 0 0 / 100% calc(100% - 12px) no-repeat var(--page)`
  (the bottom strip is snow-coloured so a fractional SVG edge never shows a sky hairline).
- Wrapper absolutely positioned `left:0; right:0; bottom:-1px; line-height:0`; SVG `display:block; width:100%;
  height:auto; aspect-ratio: 2172 / 724`. Section `overflow:hidden` clips the 1px overhang.
- Below 900px the wrapper becomes an in-flow band at the end of the hero: `position:relative; top:1px;
  height:230px; overflow:hidden`, SVG `position:absolute; right:0; bottom:0; width:max(100%, 720px)` —
  on phones this shows the right part (sun, stag, big firs), on tablets the whole drawing.
- Keep the layout so the page's top offset lands on whole pixels (the nav has a fixed height of 62px, 58px
  under 900px) — half-pixel offsets blend the drawing's bottom row.

## 3. Front page

Order: nav → hero → gallery (with decorative frame) → footer. One fluid document; breakpoints 1400, 1200,
900, 700, 600 (the media queries in `HELMET` are the reference — port them, do not invent new ones).

### Nav
Logo "Juleflet.dk" 28px/600 `--deep`; links **Skabeloner · Design · Sådan gør du · Om** (15px/500 green; active = red
text with a 2px red bottom border); right: paper colours (see below), EN pill, GitHub pill with star count.
Height 62px, padding 0 40px,
1px `--line` bottom border, `--page` background. Below 900px: padding 0 16px, height 58, logo 24px, links and
GitHub pill hidden, a 44px burger button (white, 1.5px `--line` border, radius 10) opens a menu with
Skabeloner, Design, Sådan gør du, Om, the paper colours, EN, GitHub. Design is the design page (`/design/`). Adapt the existing `PageHeader.svelte`.
Without JavaScript (`html.no-js`) the burger is swapped for a `<label>` of a visually hidden checkbox that
opens the same menu by CSS alone; with JavaScript both are `display: none`. The menu is shown by an `open`
class, not the `hidden` attribute, because Tailwind's preflight makes `[hidden]` `display: none !important`.

**As built: colours in the header.** The site's paper colours live in the header (`ColorControls.svelte`), not
the footer, as three round buttons of one size: 22px circles (1px `--line` border) in the right-hand actions
before EN and GitHub from 900px up, 28px in a labelled row "Farver" / "Colours" in the burger menu below that,
each in a 44px target. The one that is on wears a 2px `--green` ring (outline, 1px offset).
1. **Rød og hvid / Red and white**: a circle split left | right into white and red. A press puts the classic
   pair on and turns the colourful mode off; pressed again while the classic pair is on, it swaps the sides,
   and its split follows. Ring: the classic pair either way round, colourful off.
2. **Farverig / Colourful**: a plain 2×2 grid of four papers, no gaps. Each press reshuffles (below), and the
   grid with it: in the mode its cells show the strong papers of the first four pairs of the shuffle that
   come from different colour families (red, green, blue, gold, purple; `palette.iconPairs`, the `--pal-icon-*`
   variables, fading over 0.4s), with it off the palette's rowan red, spruce, navy and gold. Ring: colourful on.
3. **Egne farver / Your own colours**: the visitor's own pair, kept apart from the pair on show
   (`juleflet:custom-colors`, `colors.getCustomColors`; before the first save a custom pair on show counts as
   it), split like button 1 whenever one exists, otherwise a calm conic ring of the palette's pale papers. Ring:
   a non-classic pair on show, colourful off. A press opens a dialog (the site's `Modal`: focus inside, Escape
   and Back close it, focus returns to the button; full width on a phone) on that saved pair (or, before there
   is one, the pair on show), with a split-circle preview, the two native colour pickers, a swap button, the
   palette's twelve pairs as quick picks (named in both languages, the dialog's pair ringed) and "Færdig" /
   "Done". Changes apply live, are saved as the visitor's pair, and turn the colourful mode off. "Færdig" puts
   the dialog's pair on even with nothing changed, so a visitor can go back to a pair made earlier; Escape,
   Back and the scrim only close.
The rings and the pictures come from `html.colorful`, `html.paper-flipped` / `html.paper-custom`,
`html.paper-has-custom` and the `--paper-*`, `--custom-*` and `--pal-*` variables, all set before first paint
by the head's inline script from `julehjerte-colors`, `juleflet:custom-colors` and `juleflet:colourful`
(`colors.paperKind` is the rule), so a reload shows the right
state, and the hearts in the visitor's pair, from the first frame. `aria-pressed` on the first two;
`aria-haspopup="dialog"` on the third. GA4: `paper_colors {source: classic | flip | custom | preset | saved}` (`saved`: "Færdig" putting the saved pair
back on) (a custom
colour is counted on the picker's `change`, not every `input`), and `color_mode` as below. The editor's header
has none (the editor has its own colour controls in its panel). Without JavaScript the group is hidden.

**As built: colourful mode.** Each press of the colourful button turns the mode on and deals every heart
that follows the site's pair a new random pair from `$lib/utils/palette`: twelve Scandinavian Christmas pairs,
lighter paper left, darker right (so the ribbon is the strong colour), each ≥ 2.2:1 between its papers; the one
whose light paper is nearly the page's `#f9f9f3` (ochre/white) gets a hairline outline. The site's own red and
white is not among them (too bright beside the rest; it has its own button): its place is taken by "Rønnebær og
hør" / "Rowan and linen", `#e7e3dd` / `#9b3b37`, the same idea greyed down. Two
steps: each heart has a fixed *slot* in its markup (`data-pair` and `--pair-left/-right/-edge` reading
`var(--pal-<slot>-l/-r/-o, <unshuffled pair>)` on HangingHeart's `.hang` and the heart page's thumbnail), where
gallery hearts take the slot at their position in the gallery order, cycling the twelve, so no card shares a
neighbour's slot at any of the grid's 2–6 columns, and other hearts (Mine hjerter, shared) a hash of their id;
then a press draws a random permutation of the palette (never the one on show) that says which pair each slot
shows, set as the `--pal-*` variables on `<html>`. Being one-to-one, it keeps the neighbour rule; no slot or
pair is fixed. The permutation is stored as "3,0,7,…" under
`juleflet:colourful` (the first version's "1" reads as unshuffled), "0" once the mode is turned off, and an inline
head script sets the class and the variables before first paint, so a reload shows the last shuffle with no flash.
The mode is the default (since 2026-10-22, the owner's wish): with nothing stored, the head script deals a first
visit a shuffle of its own and stores it, unless a pair is stored from before (`julehjerte-colors`), which stays
on show; red and white is a press of the first button away. app.css maps the slot's pair
onto the heart's `--paper-*` tokens and HeartWeaveFill's `paper-l`/`paper-r` paths, cross-fading fills and
ribbons over 0.4s unless reduced motion is asked for. A heart with its own colours keeps them. The hero's
bootstrap copies a card's slot with its heart and, in the mode, draws hearts of different slots. The heart
page's big heart and thumbnail use the heart's pair; the template previews, the PDF (and its ear picture) and the
laser files keep the site's pair. The site's pair is kept while the mode is on; choosing a pair with
either of the other two buttons is what turns the mode off. GA4 event `color_mode`: `{on: true, shuffle: n}`
for the n-th press in the page view, `{on: false}` when choosing a pair turns it off.

### Hero (≥ 900px)
Grid `minmax(0,1fr) 640px`, gap 40, padding `0 40px 0 80px`, height 660px (600px below 1200px, where the
hearts block gets `transform: scale(.75)` from the top-left and the h1 drops to 48px).
Left column (padding-top 88px, gap 18, max-width 560): the H1 is now “Skabeloner til flettede
julehjerter” (52px, 44px below 1200; balanced wrapping). The wordmark stays in the navigation.
The introduction describes choosing a heart, downloading a PDF and printing on A4, and links to the guide.
Primary “Se skabeloner” (arrow) → `#skabeloner`; outline “Design dit eget hjerte” (pencil) → editor.
Both actions stay visible on phones, wrapping when needed.
Right column: a 640×560 block with five hanging hearts at absolute positions, DOM order as listed so long
ribbons pass behind shorter hearts: (left 230, size 96, ribbon 300, delay 4.4s), (470, 125, 240, 3.5s),
(300, 170, 120, 1.4s), (40, 220, 40, 0s), (500, 140, 26, 2.6s).
Both hero blocks (the five-heart desktop set and the three-heart stacked set) stay in the markup at every
width and are switched with `display: none`, deliberately: the server render and the first client render have
to be identical, so the choice cannot be made from a media-query store. It costs eight prerendered hearts.

**Random hearts:** the page is prerendered with the fixed set `nemt-hjerte, snowflake, jul, classic-3x3,
stjerne`, and a short inline `<script>` emitted straight after the gallery swaps in five distinct random ones
while the page is still parsing (`$lib/front/heroBootstrap`, `front/HeroBootstrap.svelte`). It picks gallery
cards, clones each card's finished SVG into the slot, renames the clone's clip-path ids, copies the ribbon
colour and rewrites the slot's `#heart-<id>` link and its label. So it needs no heart data and no app: it
runs before any module script and before DOMContentLoaded, and the hero is filled before the first paint.
The slots are `visibility: hidden` until it sets `html.hero-ready`, so no frame ever shows the fixed set —
that set exists for `html.no-js` and for crawlers. Sizes and positions never change, so there is no layout
shift, and no fade: the hearts are there from the first frame that has anything in it. Never repeat a heart
within the set; user-created hearts are not in the HTML, so they are excluded by construction. The load
function reads the draw back off `html[data-hero-hearts]` so hydration renders the same links.

**Sky behind the text:** from 900 up the front page hides the drawing's first two stars and first five snow
dots (`#stars > use:nth-child(-n+2)`, `#snowflakes > circle:nth-child(-n+5)`, Hero.svelte): somewhere between
900 and 1920px each of them falls inside the text column, and one star sat on the paragraph's words (QA,
2026-10-18). Hidden, not moved, so the drawing's box and the hill line are unchanged; the heart page and the
phone band keep them.

### Hanging heart component (`HangingHeart.svelte`, props: design or markup, colors, size, ribbon, delay)
```
.hang  { display:flex; flex-direction:column; align-items:center; width:{size}px; max-width:100%;
         transform-origin:50% 0; animation: sway 7s ease-in-out infinite alternate; animation-delay:{delay}s }
ribbon { width:max(8px, round(size*0.055)px); height:{ribbon + round(size*0.24)}px; background:var(--red);
         filter: drop-shadow(0 8px 12px rgb(28 51 41 / .16)) }   /* same shadow as the heart; painted first,
                                                                    so only the length above the cleft shows one */
.heart { position:relative; width:100%; aspect-ratio:1/1; margin-top:-24% }   /* the ribbon runs on behind the heart into the cleft */
.heart svg { display:block; width:100%; height:100%; filter: drop-shadow(0 8px 12px rgb(28 51 41 / .16)) }
@keyframes sway { from { transform: rotate(-1.4deg) } to { transform: rotate(1.4deg) } }
@media (prefers-reduced-motion: reduce) { .hang { animation:none } }
```
The heart itself is the existing `PaperHeartSVG` (read-only render), white + red as today — drawn at
prerender time and handed to the block as `markup` on the front page, where the browser never rebuilds it
(see `$lib/front/galleryHearts`). A frozen heart cannot repaint itself, so the footer's swatches reach its
paper through the `--paper-left` / `--paper-right` tokens instead; the ribbon stays a real element and
follows `--paper-right` too (a heart with its own colours keeps its own right-hand colour).

### Gallery
`main.gallery` max-width 1280, padding `0 40px 56px` (→ `16px 24px 40px` < 900, `16px 16px 32px` < 600),
`id="skabeloner"`. The "Skabeloner" heading is visually hidden (kept for the nav anchor and screen readers); the gallery starts with its first category. **No help text.**

The gallery follows the hill line (docs/redesign/GALLERY-CURVE.md, owner's decision 2026-10-17, design
variant "E"). From 900 up `.gallery-wrap` is pulled up so the gallery's top — the bar's top — sits on
`hillTop`, the highest point of the drawing's `snow-field` top edge inside the content column; the first
category's first row starts 6px under it (behind the transparent bar). Every grid column is a strand
(amendment 3): `drop_k` is the hill under the column's centre less `hillTop`, 54px more when that centre is
under the chips, and every card in column k, in every category, hangs at `translate: 0 y_k` — so the hill
shows in every row and rows in a column stay 28px apart. At rest the chips are right-aligned, each on the
curve. Scrolling pushes them (amendment 1, all scroll-linked, no transitions): the bar's box is L — the
largest chip lift — taller on top and sticks at `top: -L`; chip i sits at `translateY(clamp(s − H, lift_i, L)
− L)`, so the top of the screen carries the chips straight down until they are flat, and only then does the
bar stick; they stay right-aligned in the stuck bar too (the wordmark keeps its room from 900 up and only
fades in). The strands are pushed the same way: `y_k = drop_k + clamp(s + bar − (rowTop + drop_k), 0, D −
drop_k)`, with `rowTop` the first row's laid-out top (H + 6), `bar` the stuck bar's visible height and `D =
max drop_k`, so the stuck bar's bottom edge carries each strand down until all are level at D; from there
the gallery scrolls as a flat grid, D below its layout. A frame writes one custom property per column on the
gallery (`--strand-0` … `--strand-n`); each card carries `--strand: var(--strand-k)` and `translate: 0
var(--strand, 0px)` (the `translate` property, so the card's hover scale stays; chips use it too). "Mine
hjerter" is not a strand and gets D more top margin; gallery categories' `scroll-margin-top` is D less, and
the scroll-spy adds D to their tops, so a chip lands the level row just under the bar. The geometry is
`$lib/front/hillLine`; `Gallery.svelte` measures (`[data-scene-land] > svg`, on mount and with a
ResizeObserver) and hands the bar its chip lifts and the categories the column count. Before hydration an
inline script (`$lib/front/strandBootstrap`, GALLERY-CURVE.md amendment 4) works out the same pull-up and
strands from the viewport width and leaves them on `<html>`, so the first paint already hangs the cards from
the hill; the stylesheet's 1440 estimate `-100vw * 226 / 2172` is only the fallback without script. `z-index: 1` stays so the gallery paints over the scene. Below 900
none of this applies: the landscape is an in-flow band, with the scroll hint just above it.

A card's name and difficulty sit right under its heart's tip (12px at 1440, 9px on a phone), whatever its
ribbon. From 900 up every card is the heart plus 120px tall, since the strands' push moves rows a card's
height apart, and the slack for the longer ribbons is below the name; narrower, a card is as tall as what is
in it. Until 22 Oct 2026 the name stood at the card's foot, 19–59px below its heart at 1440 and 58–98px on a
phone, where that was further than the next row's ribbon (32px; the owner: "the text is closer to the heart
below it, than to the heart above it that it belongs to").

Scroll-spy: the current chip belongs to the last section whose top has reached the bar's bottom edge plus 8px
(1px slack), measured with `getBoundingClientRect()` on scroll (passive, one `requestAnimationFrame` per frame)
and on resize. At the bottom of the page the last section is current, since the last rows are too short to
reach the bar; above the first section — and whenever the bar has not yet stuck — none is. The rule is the pure
`currentSection()` in `$lib/front/scrollSpy` (`activeSection()` plus "none until stuck, then at least the
first"). When the current chip changes, the chip row scrolls just enough to
show it (the row only, not `scrollIntoView()`, which may also scroll the window and cut a smooth jump short).
A chip is a plain anchor (keyboard accessible, the URL hash updates, `?selected=` is kept). For that one jump the
bar puts `smooth-anchors` on `<html>`, which app.css turns into `scroll-behavior: smooth` under
`prefers-reduced-motion: no-preference`; it is not site-wide, because on `<html>` it would also animate
SvelteKit's scroll resets and restorations. Sections get `scroll-margin-top: calc(var(--gallery-bar-height) +
8px)`, the variable set on the gallery from the bar's measured height (49px before hydration), so a row lands
just under the bar; the sections space themselves with `margin-top` rather than `padding-top`, so their box —
what the anchor lands on and the spy measures — starts at the row.

## 7. Editor (`/editor/`)

The four outer boundary curves are handles for pulling in new cuts, not editable cuts themselves.
Selecting them shows no anchor or control handles and enables no node or segment tools; double-clicking
does not insert a node. Dragging the whole edge inward creates a real cut and restores the outer edge.
That new cut supports normal editing, symmetry, undo and redo.

A node, handle or cut dragged towards a place it may not go — where its cut would cross another cut of its
lobe or itself, leave the woven square, or come closer to the next cut than the red cuts allow (1.5 of the
square's 100 units; GitHub issue #4) — stops at the nearest place it may be and slides along whatever stops it
as the pointer goes on past it, in both tabs (`$lib/editor/dragSearch`), while the line above the heart says
why. So a drag never makes a cut red; on a heart already too close, a drag may leave it as close as it was.
A cut folding too close on itself is caught where the search ends (that check costs many times the others),
so there the point stops instead of sliding.

On a touch screen (GitHub issue #12) a second finger stops any drag, undoing it, and pinches and pans; one
finger on empty paper pans. A finger hides what it presses, so it takes hold of the chosen cut's point nearest
it within 22 px, and the point keeps that distance from the finger as it is dragged, in sight; cuts take a
26 px wide touch instead of 14.

As in tiled.art, the arrow keys move the chosen node a screen pixel a press, ten with Shift: a drag
(`nudge`), so it keeps to everything a drag does, and a black point in the Escher tab moves the tiles. A key
held is one Fortryd step. F and B choose the next and the previous node on the cut. Keys with focus on a
toggle, slider, menu or dialog are theirs, not the canvas's.

The four point-type icons follow the owner's point-types reference: a diamond at a corner, a square
on a smooth curve, a square with equal handles for symmetry, and a circle for creating curve handles.
These glyphs are 24px within the existing 44px buttons. Curves use the button text colour; points are
red on white and gold on the selected green button, with gaps separating the shapes from the curves.

explain handle behaviour, and disabled editing tools say what to select first. Tooltips wrap within
288px (or the available viewport width) and sit beside the desktop rail or below the mobile toolbar.

The figure and text generators use contour topology, never the image solver. Visible outlines belong
to one sheet; invisible connecting cuts use exactly the same path in both sheets. Enclosed regions
and detached components must be woven using these shared cuts: no cut-out fields, preview overlays
or grey areas to remove from a PDF. In a four-port cell, a pair of interior connections brackets one
external port, preserving the open path pairings. Nested contours recurse, and sibling holes may
share a chain. The compiler rejects branches, closed cycles and paths ending on the wrong edge;
geometric clearance and artwork fidelity are checked before a result can be saved or downloaded.
Fine serifs and narrow gaps can need more paper than the clearance allows, even with exact
outlines: each terminal narrower than the clearance needs its own gate connection at its tip,
and a four-port cell has only four. Never refuse a heart whose weave and picture can be made.
When every construction fails clearance, recheck the completed constructions with cuts at least
10%, then 3%, then 1% of the clearance apart, so cuts on one sheet never cross or touch, and keep
exact outlines, frame, topology and fidelity checks. Bends and loops shorter than the full
clearance remain part of one cut at every spacing, so tiny glyph edges are not mistaken for
paper. Choose the widest spacing kept, then the fewest strips with narrow paper, then the
fewest sharp tips. Show the result
with a warning that names the letters next to the narrow paper ("tricky because of “F”") so the
visitor can decide whether to change them. Earlier clean results never take this path; the
robustness corpus reports these results as hard, not accepted.
Imported figure walks are split at exactly repeated vertices, and collapsed
loops are removed without changing the even-odd fill or moving any outline.
Classify nested contours using bounds and a point off the parent's boundary;
a shared starting vertex must not turn a separate component into a hole.
If a newer local attachment route fails after cells are joined or the full
sheet is validated, try the original route too. Skip this extra attempt when
the local construction itself failed; keep all clearance and fidelity checks.
For a counter already touching its parent outline, a final figure fallback may
use that existing junction as one connection and retain an invisible bridge on
the other side of an external port. The two connections must still bracket that
port and preserve open strip pairings. Do not move the outline, merge away the
counter, or create a zero-length cutting segment. Skip this fallback when the
contour forest has no counter contact.

“Tern” is a text frame, not a separate mode or control. It places the typed letters
once on the classical checkerboard, one character per square. The heart shows the board turned
45°, so each typed line is one horizontal row of the diamond: its squares touch at their corners
and share a colour, and the next line's squares sit between them. A line is centred where its
row allows, otherwise half a square to the left (to the right only if that is what connects).
The lines first pack into the diamond, with the fewest empty squares beside them in their rows,
so J / JU / JUL / JULE fills the top half of a 4×4 board and JUL / ul / b the bottom tip of 3×3. The heart is
mirror symmetric, so the placement then keeps the most lines centred; then the block sits as near
the widest row as it can; then the first line gets the wider row, else the higher one. When every junction choice of that placement leaves narrow paper, the next placement
is tried before a hard-to-cut heart (a lone Bree Serif Å then sits beside the centre). The board
is the smallest that fits and connects: abc is 3×3 with abc across the
middle row, abc / de puts de below it on the same board, abc / def needs 4×4 with abc half a
square left, a / bc / d is 2×2, ANNA 4×4, JUL 3×3, GOD JUL 7×7, J / UL / JUL / UL / J fills all
nine squares of 3×3, JUL / JU / L fills the lower five, and a single letter takes the top square
of a 2×2 board. Spaces stay plain squares. Nothing repeats: a visitor who wants a pattern types
it. Letters stay upright, all at one size: the widest, at the full height of the text, fills
its square, and narrower letters keep that size, centred, rather than growing to fill theirs (an
I as tall as the H beside it). When no layout weaves cleanly, the first is tried with all letters
5% and then 10% larger before a hard-to-cut heart (only the standard size's rejected cuts go to
that fallback), and a result with narrow paper tips is compared, as exported, with the first
layout 5% larger: a letter that shrank to match a wider one can then route without them. Every letter contrasts with its square; counters keep the square's
background colour. It is actual cutting geometry, with no preview overlays or cutouts.
