# Juleflet redesign — implementation spec

Source of truth for the visuals: the rendered mockup artboards in
`/Users/ahle/repos/julehjerte-redesign/docs/redesign/mockups/`
(`Main.dc.html` = front page 1440, `Tablet.dc.html` 1024, `TabletPortrait.dc.html` 768, `Mobile.dc.html` 390,
`Detail.dc.html`, `HowTo.dc.html`, `Om.dc.html`, `Editor.dc.html`). They are generated by `build-artboards.mjs`
in the same directory, which contains the exact CSS (the `HELMET` constant) and every markup helper
(`hang`, `card`, `categorySection`, `hero`, `detail`, `guideSvg`, `om`, `editor`, `galleryFrame`, `landPine`).
Read that file when you need an exact value; open the `.dc.html` files in a browser to see the result.
Screenshots of the mockups exist next to them (`*.png`).

The site is Danish-first with an English mirror under `/en/`. Every user-facing string below is Danish and
needs an English equivalent in `src/lib/i18n/translations.ts`.

## 1. Palette and type

Define as CSS custom properties on `:root` (replace the current blue/teal palette everywhere):

| token | value | use |
|---|---|---|
| `--page` | `#f9f9f3` | page background — identical to the landscape's foreground snow, so hero and gallery join without a seam |
| `--sky` | `#d6e1d0` | hero / detail-scene background (the landscape's sky) |
| `--cream2` | `#e6ece2` | footer, soft panels |
| `--sage` | `#b5c9b7` | inactive dots, dashed borders |
| `--sage-dark` | `#7f9c86` | secondary strokes |
| `--green` | `#2e5041` | nav links, outline buttons, icons, category headings |
| `--deep` | `#1c3329` | headings |
| `--red` | `#c41e2a` | primary buttons, ribbons, selection ring/badge, active nav |
| `--ink` | `#1e2a25` | body text |
| `--muted` | `#5f6d66` | secondary text |
| `--line` | `#cfd9cf` | borders, pills |
| `--white` | `#ffffff` | cards, buttons |
| `--gold` | `#e0b75a` | stars |
| `--blue` | `#4a90b8` | focus rings only |
| `--muted-on-sky` | `#4d594f` | secondary text painted on `--sky` (see below) |

`--muted` on `--sky` measures 4.02:1, under the WCAG AA 4.5:1 minimum for body text, so text that sits on the
hero/detail sky uses `--muted-on-sky` (5.4:1) instead; `--muted` is unchanged everywhere else. For the same
reason the focus ring is `outline: 3px solid var(--blue)` **plus** `box-shadow: 0 0 0 2px var(--page)`:
`--blue` alone is 2.60:1 against `--sky`, and the pale inner ring keeps one edge of the indicator above the
3:1 that SC 1.4.11 asks for on every background.

Font stays `'Helvetica Neue', Helvetica, Arial, sans-serif`, antialiased. Headings weight 600, h1 line-height 1.05.
Buttons: height 44, padding 0 20, radius 10, 15px/600, icon 18px + 8px gap. Kinds: primary (red bg, white text),
outline (white bg, 1.5px green border, green text), ghost (transparent, 1.5px `--line` border, green text),
dark (green bg, white text). Pills (EN, GitHub): 13px/600 green, 1.5px `--line` border, radius 999, white bg.

## 2. The landscape drawing

`landscape.svg` (2172×724) is the user's own drawing. Use the copy `landscape-lifted.svg` from the design
directory: it is identical except that the foreground snow bank is lifted a few units where the original dipped
below the bottom edge, so the drawing always ends in `#f9f9f3` snow (= `--page`). Put it in the repo as
`src/lib/assets/landscape.svg` and build a `Landscape.svelte` component that inlines it once per page
(`import svg from '$lib/assets/landscape.svg?raw'`, strip the outer `<svg …>` open tag, `<title>` and `<desc>`,
and emit `<svg class={cls} viewBox="0 0 2172 724" preserveAspectRatio="xMidYMax meet" aria-hidden="true">…</svg>`).

Its `<defs>` carry reusable ids that other inline SVGs on the same page reference with `<use href="#…">`:
`pine-a`, `pine-b`, `pine-c` (fir silhouettes: tip at (0,0), base at y = 202, width about ±65),
`snow-cap` (frost, use with `fill="#fbfcfa"` in the same group), `star` (34 units, gold), gradients
`sky`, `distant-hill`, `middle-hill`, `near-hill`, `snow`. Because of these ids the drawing may be inlined only
once per page. A fir is placed with `<g transform="translate(x tipY) scale(kx ky)" fill="#35503f"><use href="#pine-c"/><use href="#snow-cap" fill="#fbfcfa"/></g>`
where `k = height / 202`; negative `kx` mirrors it. Fir fills: `#35503f`, `#3b5d46`, `#3e5948`, `#34523f`.
See `landPine()` in the generator.

Placement rules (front-page hero; detail page is the same idea):
- Hero `background: linear-gradient(var(--sky), var(--sky)) 0 0 / 100% calc(100% - 12px) no-repeat var(--page)`
  (the bottom strip is snow-coloured so a fractional SVG edge never shows a sky hairline).
- Wrapper absolutely positioned `left:0; right:0; bottom:-1px; line-height:0`; SVG `display:block; width:100%;
  height:auto; aspect-ratio: 2172 / 724`. Section `overflow:hidden` clips the 1px overhang.
- Below 900px the wrapper becomes an in-flow band at the end of the hero: `position:relative; top:1px;
  height:230px; overflow:hidden`, SVG `position:absolute; right:0; bottom:0; width:max(100%, 720px)` —
  on phones this shows the right part (sun, stag, big firs), on tablets the whole drawing.
- Keep the layout so the page's top offset lands on whole pixels (the nav has a fixed height of 62px, 58px
  under 900px) — half-pixel offsets blend the drawing's bottom row.

### Hanging heart component (`HangingHeart.svelte`, props: id/design, size, ribbon, delay, color)
```

                                                                    so only the length above the cleft shows one */
.heart { position:relative; width:100%; aspect-ratio:1/1; margin-top:-24% }   /* the ribbon runs on behind the heart into the cleft */
.heart svg { display:block; width:100%; height:100%; filter: drop-shadow(0 8px 12px rgb(28 51 41 / .16)) }
@keyframes sway { from { transform: rotate(-1.4deg) } to { transform: rotate(1.4deg) } }
@media (prefers-reduced-motion: reduce) { .hang { animation:none } }
```
The heart itself is the existing `PaperHeartSVG` (read-only render), white + red as today.

## 7. Editor (`/editor/`)

Keep every existing tool (undo/redo, insert/delete node, corner/smooth/symmetric, straighten line/curve, …) as
44px icon buttons with tooltips — nothing removed, no labels under icons. Apply the palette: page background,
panels white with 1px `--line` and radius 12, section titles 12px uppercase `--muted`, green accents, red
primary. Top bar: back link + logo at the left; Help (icon), **Download PDF** (primary red) and **Gem** (dark
green) at the right. Right panel 340px: Symmetri (segmented Fra / Sym / Anti), Tegning, Farver, Hjertedetaljer,
Handlinger. A **"Skjul panel"** control collapses the panel so the canvas fills the width; a slim tab at the
right edge ("Vis panel") brings it back; remember the choice in localStorage. Add a "Snap til modsat side"
checkbox and a one-line hint above the canvas. The mobile editor keeps its existing stacked panels.

The canvas fills the whole area under the top bar — full width and height, no three-column grid — and the tool
rail and the panel **float over it** as white cards with `--shadow-panel`. So does the drawing surface: the SVG
is the whole canvas area (`inset: 0`), so a zoomed or panned heart carries on under the rail and the panel and
out to the window edges. Clipping it at their edges was the one thing that gave the floating away.

The rail's and the panel's widths survive as two insets (`--editor-rail-inset`, `--editor-panel-inset`; the
panel's drops to 60px while it is collapsed) with exactly two jobs: they place the canvas chrome (hint,
selection chip, strip count, notices), and they size the **fit band** — an unpainted box, `.canvas-fit-band`,
16px in from the top and bottom and inset by the two widths, which is what the default zoom and "Tilpas
visning" target. So the heart at rest is whole and clear of both, and collapsing the panel widens the band and
re-centres it. The band is measured, not assumed: it is a real element next to the SVG, watched by the same
ResizeObserver, and where there is none (the fixed-size instance, the mobile editor) the fit falls back to the
surface itself.

**Gem** means something. A heart that is already in "Mine hjerter" keeps autosaving into it, so re-opening one
and nudging a curve needs no button. A heart that is *not* — a blank editor, a copy of a gallery heart
(`?from=`), a shared `#design=` link — writes nothing to the collection until "Gem" is pressed; otherwise every
stray colour click would leave a "Mit hjerte" card behind. Its work in progress goes to one draft in
localStorage instead (`paperheart.draft`: the design, where it came from, when it was written), on the same
debounced path autosave uses. Open the editor as a new heart with a draft waiting and it is offered back in a
canvas notice — "Du har en kladde fra sidst. Fortsæt hvor du slap?", *Fortsæt* / *Start forfra* — read after
mount, never during render. Saving the heart, discarding the draft, or starting another one clears it.

Colours belong to the heart, not to the browser: a design may carry `colors: { left, right }` (two hex values),
and the Farver section edits them with two real colour inputs plus "Byt". Gallery hearts carry none and follow
the site-wide colour store as before; a heart the visitor draws stores what was picked, and saving, sharing and
the PDF carry it. Old saved hearts without colours keep rendering in the site-wide pair.

## 8. Constraints and process

- SvelteKit static adapter, `trailingSlash: 'always'`, everything prerendered; keep it that way.
- Two languages via `src/lib/i18n/translations.ts`; every new string in both `da` and `en`; keep the
  translations test passing. Danish is the default (no prefix), English under `/en/`.
- Keep working: selection state in the URL (`?selected=`), the PDF generation and its settings dialog, sharing by
  hash link, user hearts in localStorage, analytics events (never with LaTeX/heart content), OG images, sitemap.
- Prefer lucide icons already in the repo; otherwise copy the small stroke icons from the generator's `I` map.
- Run `npm run check`, `npm run lint`, `npm test` and `npm run build` before you finish; fix what you break.
- Commit your work on your branch with clear messages. **Never push.**
- Work only inside your assigned worktree. `/Users/ahle/repos/julehjerte` (the main checkout) contains
  someone else's uncommitted work: never modify, stash, checkout or clean it. Reuse its `node_modules`
