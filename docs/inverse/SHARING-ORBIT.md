# Shared-cut repair with combined square symmetries

Near-coincident cuts can leave long hairline seams with very little pixel-area
error. The final shared-cut pass addresses this after fitting and matching-sheet
selection. It previously skipped square mirrors, half turns and combinations of
symmetries because splitting one cut invalidated the control-point pairing with
its partners.

The repair now supports every combination of `mirrorX`, `mirrorY`, `rotate180`,
`transpose` and `antiTranspose`. It preserves the complete group generated by
the requested transformations, including a transposed-sheet constraint when the
selected templates already match. Existing independent, transposed and
anti-transposed repair routes retain their previous implementation.

`shared-span.js` constructs the same proposed common Bézier span as before and
can also return its subdivisions in each original path's parameter frame.
`sharing-orbit.js` finds transformed partners by their endpoints, including
reversed travel, and propagates the subdivisions through the square transforms,
the proposed shared interval and existing shared cubic occurrences. Original
corners remain subdivision boundaries. The normal affine constraints then project
all corresponding controls together. Rebuilding the curve graph afterward stores
newly coincident curves once, so invisible cuts remain exactly shared in exports.

Cuts in the same symmetry orbit need compatible proposed intervals. Small
endpoint discrepancies use the existing 0.05-segment alignment tolerance;
incompatible proposals are rejected. Partition growth is bounded: overlapping
constraints that would keep generating subdivisions cannot consume the rest of
the search budget. This is a conservative local repair, not a guarantee that
every near-coincident span admits a valid shared replacement.

Acceptance still requires non-increasing mask error at both search resolutions,
all requested symmetries, valid cutting geometry, no additional sharp turns and
the existing bend and paper-core checks. Final selection additionally checks the
original source mask and its image features. Deliberate narrow input lines are
retained. Neither the image nor the acceptance thresholds are changed.

The subsequent [joint chord projection](CHORD-PROJECTION.md) also supports
within-curve symmetry. Its parameter reversal participates in subdivision
closure, while the distinct spatial maps are solved as joint point constraints
rather than assumed to form a finite square-transform group.

## Regression fixtures

`fixtures/symmetric-frame.mjs` defines four shared diagonal spans from known
straight cutting paths. Normal perturbations of 0.16 mm produce near-coincident
cuts while retaining the original square symmetries. The fixture is supplied only
to cleanup tests, never to a fresh inverse initializer.

All 31 nonempty square-symmetry combinations are exercised on two cuts per
sheet. Seven combinations that permit unequal counts are also exercised with
two and four cuts. Each removes all four seams, increasing exactly shared
length from zero to 84.85 mm on a 100 mm square and reducing the 400-pixel
binary-mask disagreement from 0.83% to zero. All geometry, material and symmetry
checks pass; another cleanup pass makes no change.

The independent 1600-pixel resvg comparison checks the actual exported controls.
Fractional coverage error for the two-cut frame falls from 0.6967% to 0.1135%.
The four seam interiors agree exactly with the known design. Slightly perturbed
surrounding cuts remain, so a zero binary error at the source resolution does
not mean every curve reproduces the unperturbed design exactly.

Additional tests cover reordered paths, genuinely requested narrow lines,
expired budgets and constraints absent from the input geometry. The production
browser fixture replay exercises combined mirrors, both diagonal symmetries,
and unequal counts. It is a controlled cleanup replay; fresh fitting and editor
export are checked separately by the Paint workflow suite.

```sh
node --test scripts/inverse/sharing-orbit.test.mjs scripts/inverse/sharing.test.mjs
node scripts/inverse/sharing-orbit-browser-test.mjs
```

## Production regression checks

The complete test run passes 783 application tests and 331 engine tests (one
optional application recording is skipped), with zero type-check errors, seven
existing Svelte warnings, and successful lint and build checks. All 12 controlled
cleanup replays pass in Chromium, Firefox and WebKit.

All 22 regular Hunodan photographs retain byte-identical exported geometry
compared with the previous release checks. Serial Node preparation, fitting,
validation and export have a 5.08-second median and an 8.02-second maximum. This
includes progress geometry and retained candidate checkpoints; photograph
decoding and independent export rasterization are measured separately. These
are whole-fit timings, distinct from the short controlled cleanup fixtures.

The 32 free-border perturbation cases also retain byte-identical geometry, with
all existing quality checks passing (4.47-second median, 7.64-second maximum).
All 18 fresh Paint workflows pass across Chromium, Firefox and WebKit: star,
Hunodan photo, circle, and matching, independent and anti-paired hats. Their
exported geometry and source-mask errors match the preceding release exactly;
the matching hat retains 41 shared spans through editor conversion.

[SHARING-ORBIT-VALIDATION.json](SHARING-ORBIT-VALIDATION.json) records the browser
measurements, source and artifact hashes, and comparison criteria. All 59 served
engine/worker source files match the benchmarked checkout. The preview remains
